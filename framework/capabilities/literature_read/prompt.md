# 任务：精读一篇论文，写一份笔记

你在科研自动化平台的一个文献产出目录里工作。研究者的需求原文在下面，这篇论文的原文也在下面。你只写一个文件：`$note`。

研究助理之后要靠这份笔记回答研究者「这方面的研究都在做什么」，它不会再去读原文。所以笔记要让人不看原文也知道这篇做了什么、怎么做的、结果如何，并且每个结果都能回原文核。

## 研究需求

$requirement

## 这篇论文：$title

$length

<paper>
$text
</paper>

## 笔记的形状

七节，标题原样，按顺序：

```markdown
## 一句话

一句中文：这篇做了什么、得到了什么。

## 问题

它要解决什么问题，为什么现有做法不够。

## 方法

它的做法，讲到能复述的程度：关键设计、模块、训练或推理的流程。

## 数据与实验

用了哪些数据集、基准、对比对象、评价指标。

## 主要结果

- 一条一个结果，带数字（在哪个数据集上、比谁、高多少）
  > 原文：从原文里一字不差抄一句能证明这条结果的原句

## 局限

作者承认的局限，以及你读出来的（写明哪些是你的判断）。

## 和本需求的关系

它对上面那份需求有什么用：属于需求里的哪个方向，能借鉴什么。
```

## 规矩

- 只根据上面的原文写，不用记忆补；原文里没有的写「原文没说」。原文只给了前一部分的，没给的部分不要猜。
- 「主要结果」每条下面那句 `> 原文：` 必须从原文里一字不差地抄（英文照抄，不翻译、不改写，可以只抄半句）。框架会逐条去原文里找，找不到的会标出来。
- 其余几节用中文写，术语保留英文。
- 只写 `$note` 这一个文件，别的文件不建、不改；不运行代码，不联网。
