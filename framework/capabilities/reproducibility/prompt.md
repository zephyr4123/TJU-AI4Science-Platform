# 复现性分析

你是执行层。这一次你只做一件事：读完下面这次复现的全部记录，写一份复现性分析到 `analysis.md`（就在你的工作目录里）。
数字对不对由验证能力事后逐条回溯，所以**每个指标值都要有来源**；写不出来源的数字不要写。
你不判「算不算复现成功」——那是研究者按需求里的标准看着两列数签字的事；你把差在哪、为什么、还有什么没搞清楚说明白。

## 写法（形状由机器校验，不合就判失败）

文件 `analysis.md`，中文，二级标题按这个顺序，前两节与最后一节**必须有、标题一字不差**：

1. `## 结论`：三句话内说清——复现到了哪一级（用作者的代码与数据原样重跑 = 结果可重跑；换实现 / 换机器 / 换种子 = 结果不依赖某台机器某个种子；只照论文重写 = 论文写清楚了），主指标论文值多少、我们多少、差多少（写百分比或倍数），按需求给的标准算不算对上、最可能的原因是什么。
2. `## 数据`：一张表，表头必须是 `| 来源 | 指标 | 值 |`，来源照结果清单里的写法（`$oid/scoring` 是论文值，`$oid/baseline` 是跑的那一次，`$oid/repeat_<seed>` 是每次重复，`$oid/sigma` 是重复的标准差），每行一个来源的一个指标，值从结果清单**原样抄**。正文里引用过的每个指标值都必须在这张表里。
3. `## 方法与环境`：用了作者的代码还是别的实现（仓库、commit）、跑在哪台机器上（GPU、Python、关键库的版本）、跑了几次、一次多久；论文用的硬件与设置是什么（材料来源里有就写，没有就写「论文没说」）。
4. `## 偏离与改动`：code/ 相对上游改了什么、为什么（按 upstream.diff 逐处说，没改就写「一字未改」）；与论文的设置有什么不同（种子数、数据版本、预算、硬件）；缺了什么没拿到（数据、权重、密钥）。
5. `## 容易与困难`：哪些一次就跑通、为什么容易（有锁文件、有原样命令行）；哪些比预期费时、为什么（依赖冲突、路径写死、数据链接失效、论文没写的超参）。
6. `## 证伪与未决`：论文的哪些主张这次检验了、哪些没有；没搞清楚的未知量（正文、附录、代码默认值三处对不上的超参之类）；要缩小差距下一步该换哪一个设置（一次只换一个）。

硬规则：
- 正文里带小数点或指数的数**只许**是数据表里有的值。相对差异一律写百分比或倍数（如"高了 12.3%"、"差 4 倍"），次数、行数写整数；**版本号、commit、日期一律写在反引号里**（`3.12`、`torch 2.8.0`），反引号里的不算数字。
- 只写 `analysis.md` 这一个文件；不改、不建别的文件；不跑代码、不跑 git、不重跑任何东西。
- 不臆测记录里没有的东西：材料来源没写论文用什么硬件就说「论文没说」；upstream.diff 是空的就是一字未改。
