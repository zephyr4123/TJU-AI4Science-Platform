**人**：你好,你有什么能力能够组装

**agent**：你好。目前平台一共有 **7 项能力**可以拼，按科研的七个阶段分布如下：

**设计阶段（对任务包操作）**
- **起任务包**：建目录、把你的材料搬进去、写好环境记录，留下带说明的模板让我们一起填
- **接任务**：模型照着设计说明写评分脚本和代码草稿，框架再做格式检查和校验
- **跑基线**：用你现有的策略跑出基线成绩，重复几次算出噪声大小 σ

**实验阶段**
- **开一次实验**：把任务包搬进独立工作区，记下基线
- **一轮一轮改**：模型每轮改代码、独立跑分，成绩超过噪声门槛才留下

**分析阶段**
- **写分析**：读实验记录和结果，写一份每个数字都能回溯的分析

**验证阶段**
- **验证**：不用模型，纯机器核对分析里的每个数字是否能追溯到原始结果

**还没有的**：文献、假设、写作三个阶段目前是空的，另外「撒一批起点去探尽头值」这个功能也还没做。

现成的拼法有两条：
- **接一个真任务**：起任务包 → 接任务 → 跑基线（中间要你发布需求）
- **auto-research**：开实验 → 一轮轮改 → 写分析 → 验证（最后要你验收结果）

你也可以自己拼，比如「开实验 → 改 2 轮 → 写分析」跳过验证做个快速预览。你手头现在是有一个想跑的任务，还是想先看看这几条流具体怎么走？

**人**：那我有一个疑惑啊,比如说我现在要做一个某某某任务,我和你对接完需求之后,准备开始干活,用workflow去做

**agent**：是隔离的，分两层：

**任务包**：`tasks/<任务名>/`，一个任务一个目录。里面放你的材料（`data/`）、环境记录（`env/`）、需求说明（`manifest.yaml` 和 `design.md`）、裁判脚本（`harness/`）、代码（`code/`）、基线结果（`run_0/`）。这是「题目」本身，发布之后就冻结了——改了说明就得重新发布。

所以一个任务可以开多次实验（比如换个预算再跑一次），互不干扰；两个任务之间完全不碰。任务名是你起的，小写英文加连字符，比如 `boehm-nll`。

领域相关的东西（执行层用的技能、约定）在 `domains/<领域>/`，多个任务可以共用一个领域包；开实验时也会快照一份进 run。

要查的话：`ai4sci show task tasks/<任务名>` 看任务包状态，`ai4sci show run <run 名>` 看某次实验走到哪。

**关于会不会逃出目录，实话说，分两层：**

**执行层（真正改代码的模型）**：有硬约束。接任务时框架只放行它写 `harness/` 和 `code/`，跑实验时只放行 `work/code/`，越界写了框架直接判不通过。裁判脚本被封了校验和，改了会被抓出来。这一层是框架在管，不靠模型自觉。

**我（协调层）**：约束比执行层弱。命令这一侧是硬的——我只能运行 `ai4sci` 的子命令，不能裸跑 python、不能 cp/mkdir、不能拼管道，每条命令都要明写目标路径。但我手上有读写文件的工具，指南要求我填 `manifest.yaml` 和 `design.md`，就是靠这个改的。理论上我能改别的文件，这靠的是规则约束加你能看见：账本和 git 的对账会把手改记录抓出来，发布过的说明改了钥匙就失效。

所以准确地说：执行层被框架关在笼子里；我是被规则和事后审计约束的，不是被沙盒关着的。这个差别你知道就好，是平台目前的实际状态。
